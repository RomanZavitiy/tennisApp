## Контекст

- Уже є: 4.1 (`lib/rating/starting-elo.ts`), 4.2 (ELO і лічильник матчів у `User`), 3.8–3.9
  (ранжування стрічки за ELO).
- Рішення з `decisions.md` (2026-10-14), обов'язкові:
  - **Формула:** `E = 1 / (1 + 10^((Rb − Ra) / 400))`; лише перемога/поразка; K = 40 для перших
    10 підтверджених матчів гравця, далі K = 20; кожен гравець — свій K; `Math.round`; мінімум 100.
  - **Рахунок:** 2–3 сети. Сет: 6–0…6–4, 7–5, 7–6. Третій сет — звичайний або супер-тай-брейк до
    10 з різницею ≥ 2. Переможець — хто взяв 2 сети. Retired не вноситься.
  - **Підтвердження:** суперник підтверджує або оскаржує; автопідтвердження через 72 год;
    оскаржений результат на ELO не впливає.
  - ELO рахується лише для синґлів; у парній оферті форми результату немає.
- Прочитай «Нотатку передачі» з сесії 03 (системні повідомлення в тред).
- `CRON_SECRET` уже є в env (людина додала перед сесією).

## Завдання

1. **4.3 `computeEloChange()`** у `lib/rating/`. Тести: перемога сильнішого дає менший приріст;
   межа 10/11 матчів для K; нижня межа 100; однакові входи → однакові виходи.
2. **4.4 Поля `MatchResult`:** гравці, рахунок (структуровано, не рядком), переможець, хто вніс,
   статус (`PENDING` / `CONFIRMED` / `DISPUTED` / `NO_SHOW`), `autoConfirmAt`, ELO до/після
   для обох, зв'язок із прийнятою заявкою синґл-оферти. `NO_SHOW` використає сесія 05.
3. **4.5 Zod-схема рахунку.** Тести: `6-4 6-3` ✓; `6-4 3-6 10-8` ✓; `7-6 7-6` ✓; `6-6` ✗;
   `6-4 3-6 10-9` ✗; `6-4 6-4 6-4` ✗; переможець не узгоджений з рахунком ✗.
4. **4.6 Форма результату.** Внести може лише учасник прийнятої пари синґл-оферти, після часу
   старту матчу; повторне внесення заблоковане; у парній — немає форми, server action теж
   відмовляє. У формі передбач місце для варіанта «Opponent didn't show up» (вимкнений, з TODO
   на сесію 05) — щоб не переробляти UI.
5. **4.7 Підтвердження/оскарження.** Лише інша сторона. При внесенні `autoConfirmAt = now + 72 год`.
   Системне повідомлення в тред при внесенні, підтвердженні й оскарженні.
6. **5.8 Захищений cron-ендпоінт** `/api/cron` (виклик без `CRON_SECRET` → 401). Задача:
   автопідтвердження прострочених `PENDING`. **Перевір поточні ліміти Vercel Hobby для cron**
   (на момент планування — не частіше разу на добу). Якщо цього мало для майбутніх нагадувань
   (сесія 07 потребує погодинного запуску) — заплануй виклик через Supabase `pg_cron` + `pg_net`
   або GitHub Actions `schedule` і запиши вибір у `decisions.md`. Розклад — у коді/конфігу.
7. **4.8 Застосування ELO** в одній транзакції при підтвердженні (ручному або авто): ELO обох,
   знімки до/після, `matchesPlayed++`. Подвійне підтвердження застосовує зміну один раз — тест.
8. **4.9 Історія матчів на `/players/[id]`:** поточний ELO, список підтверджених матчів
   (суперник, рахунок, ±ELO). Непідтверджені публічно не показуються.
9. **E2E флоу №4:** гравець вносить результат → суперник підтверджує → ELO обох змінився.
