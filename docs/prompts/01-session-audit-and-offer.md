# Сесія 01 — Аудит стану, процес v2 і доробка оферти (слайси A + B)

## Роль

Ти — senior full-stack інженер (Next.js App Router, TypeScript strict, Supabase Auth/Storage/
Realtime, Prisma, Postgres RLS, Vitest, Playwright). Ти працюєш у цьому репозиторії автономно за
правилами `AGENTS.md` і доводиш слайс до зеленого PR без проміжних зупинок.

## Контекст

- Продукт: MatchFinder Kraków — веб-застосунок для пошуку партнера з тенісу в Кракові: оферти
  спарингів, заявки, чат, ELO-рейтинг, каталог клубів із посиланням на їхнє бронювання.
- Джерела правди: `AGENTS.md`, `docs/PLANNING.md` (план v2 від 2026-10-14), `.agents/decisions.md`,
  `.agents/MEMORY.md`.
- План v2 щойно замінив план v1. Чекбокси v1 були не синхронізовані з кодом: частина задач,
  позначених ⬜, фактично виконана (позначені 🔎 у розділі «Що вже є»).
- План v2 полегшує процес: слайс = один PR; e2e лише для 4 критичних флоу; `decisions.md` лише
  для незворотних рішень.

## Завдання

### Частина 1 — Слайс A (синхронізація)

1. **Архів плану.** Якщо `docs/archive/PLANNING-v1.md` не існує — збережи туди попередню
   версію `docs/PLANNING.md` з історії git (`git log --follow docs/PLANNING.md`, потім
   `git show <коміт>:docs/PLANNING.md`) без змін.
2. **0.24 Аудит.** Для кожної задачі з позначкою 🔎 і ⬜ у `docs/PLANNING.md` перевір код, тести й
   міграції. Критерій — DoD задачі з плану v1 (`docs/archive/PLANNING-v1.md`), якщо в v2 він
   посилається «як у v1». Позначки:
   - DoD виконано → `✅`;
   - виконано частково → лиши `⬜` і допиши під задачею `Залишок: …` (одне речення);
   - не почато → лиши `⬜`.
   Не виправляй знайдені прогалини в цій частині — лише фіксуй.
3. **0.25 Оновити `AGENTS.md`** під розділ «Процес (полегшений)» плану v2: §7 (e2e лише для 4
   флоу), §8 (слайс = гілка = PR), §10 (`decisions.md` лише для незворотних рішень; 4 умови
   зупинки агента). Не змінюй стек і заборони з інших розділів.
4. **0.26 Перенести «Ухвалені рішення (2026-10-14)»** у `.agents/decisions.md`: кожен рядок
   таблиці — окремий датований запис із причиною. Старий запис про мінімальний вік 16 позначити
   «замінено записом від 2026-10-14».

### Частина 2 — Слайс B (оферта)

5. **1.21 Вік 18+.** Zod-схема профілю відхиляє вік < 18; рівно 18 сьогодні — приймається.
   Тести межі дня народження. Тексти онбордингу оновлено. Користувач, якому вже менше 18
   (тестові акаунти), бачить зрозуміле повідомлення, а не помилку 500.
6. **3.22 Статус корту.** Поле `courtStatus` (`BOOKED` / `WILL_BOOK` / `ANY`), дефолт `WILL_BOOK`.
   Міграція лише додає колонку з дефолтом. Поле у формі створення оферти, у картці стрічки, на
   сторінці оферти (якщо вона вже існує). Фільтр «Court already booked» у стрічці, у URL, як
   інші фільтри.
7. **3.20 Приховувати минулі оферти.** Фільтр за часом у запитах (без фонового процесу): минулі
   оферти не видно в стрічці, на карті й на сторінці клубу. Тест межі «рівно зараз».
8. Якщо аудит (п. 2) показав, що якась задача з 3.2–3.7 зроблена частково і це заважає п. 6–7,
   — доведи її до DoD у цьому ж слайсі. Інші прогалини лише фіксуй.

## Правила роботи

- Спершу прочитай `AGENTS.md`, `docs/PLANNING.md`, `.agents/decisions.md`, `.agents/MEMORY.md`.
  Потім склади план на 5–10 кроків і виконуй його без зупинок між задачами.
- Не читай увесь репозиторій. Відкривай файли, потрібні для конкретної задачі.
- Одна гілка `feat/slice-AB-audit-and-offer`, один PR. Коміти всередині — на твій розсуд.
- **Зупинись і спитай людину лише якщо:** потрібен новий зовнішній сервіс; міграція видаляє або
  перейменовує дані; нова RLS-політика відкриває читання; потрібен секрет.
- Усе знайдене поза межами слайсу записуй у `.agents/MEMORY.md`, не виправляй.

## Очікуваний результат

1. PR з описом:
   - абзац «що зроблено і чому»;
   - таблиця аудиту: `ID → стан (✅/частково/⬜) → доказ (файл, тест або міграція)`;
   - список ID слайсу B зі статусом;
   - як перевірити на preview (3–5 кроків руками).
2. `docs/PLANNING.md` з оновленими позначками і «Залишок: …» де треба.
3. `.agents/MEMORY.md` — розділ «Нотатка передачі»: що зроблено, що лишилось, що з'ясувалося
   несподіваного, що треба знати сесії 02.
4. Фінальне повідомлення в чаті: короткий звіт + список того, що потребує дій людини.
