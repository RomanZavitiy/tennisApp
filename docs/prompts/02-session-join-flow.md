## Завдання

1. **3.11 Server action «подати заявку».** Відмова: без сесії / з незавершеним профілем; власна
   оферта; минула; закрита (`FULL`/скасована); повторна заявка. Кожен випадок — юніт-тест.
   Контакти (email, телефон) сторони не бачать ніде в UI і відповідях.
2. **3.12 Прийняття/відхилення автором.** Переходи статусів — чиста функція в `lib/` з тестом
   таблиці дозволених переходів (включно з відкликанням гравцем). Лише автор оферти може
   приймати/відхиляти — перевірка на сервері. Коли прийнятих стає стільки, скільки потрібно,
   оферта стає `FULL` і нові прийняття неможливі — тести для синґлу і обох варіантів парної.
   Конкурентне прийняття (два кліки одночасно) не дає перебору — транзакція або умовний update.
3. **3.13 Сторінка оферти `/offers/[id]`.**
   - Гість: деталі + «Sign in to join».
   - Гравець: кнопка заявки, статус своєї заявки, можливість відкликати.
   - Автор: список заявок (ім'я, NTRP/ELO, кнопки прийняти/відхилити), лічильник вільних місць.
   - Усім: статус корту (`courtStatus`) і, якщо вибрано клуб, кнопка «Book on club's site» на
     зовнішнє бронювання (`target="_blank" rel="noopener noreferrer"`).
   - Неіснуючий id → 404. Сторінка — Server Component, мутації — server actions.
4. **3.14 Скасування оферти автором.** Скасована оферта зникає зі стрічки; учасники з прийнятою
   заявкою бачать «Cancelled». Якщо скасування < 12 год до старту і є прийняті гравці —
   виклич заглушку `recordLateCancellation(userId)` у `lib/rating/reliability.ts` (поки no-op з
   TODO на сесію 05) і покрий тестом функцію `isLateCancellation(startAt, now)` з межею 12 год.
5. **E2E флоу №3 (частина 1):** гравець подає заявку → автор приймає → гравець бачить статус
   «Accepted».
