# План: падел у SpinBuddy (слайси PD1–PD5)

Дата: 2026-11-16. Підстава — [HIPADEL-ANALYSIS.md](./HIPADEL-ANALYSIS.md). Правила роботи —
[AGENTS.md](../AGENTS.md). Одна сесія = один слайс = один бранч `feat/PD<n>-…` і один PR.

## Принципи

1. **Один застосунок, два спорти.** Акаунт, чат, сповіщення, надійність, модерація — спільні.
   Від спорту залежать: оферти, клуби, рівень гравця, рейтинг.
2. **Активний спорт — cookie `SB_SPORT`**, як мова в `NEXT_LOCALE`: без сегмента в URL, типово
   теніс. Перемикач у шапці. Сторінка конкретної оферти чи клубу показує свій спорт незалежно від
   перемикача.
3. **Теніс не змінюється.** Усі нові колонки мають типове значення `TENNIS`; наявні рядки, тести
   й e2e лишаються чинними.
4. **Падел — завжди пара** (4 гравці). Рівень 1.0–7.0 з кроком 0.5, зберігається в тих самих
   колонках оферти `ntrp_min`/`ntrp_max` (назва історична; перейменування колонки — окреме
   рішення, зараз не потрібне).
5. Нічого з платежів, нативного застосунку, нових зовнішніх сервісів.

      `User.padelSide` (enum `PadelSide`); міграція з CHECK-ами (падел = лише пара; рівень 1.0–7.0).
- [x] PD1.2 `lib/sport/`: константи, шкали рівнів за спортом, cookie, server action `setSport`.
- [x] PD1.3 Перемикач «Теніс / Падел» у шапці (десктоп і мобільний).
- [x] PD1.4 Стрічка `/offers` і головна показують оферти активного спорту; фільтр рівня за шкалою
      спорту; для падел фільтр формату схований.
- [x] PD1.5 Форма оферти: спорт з перемикача; падел — завжди пара, без покриття, шкала 1–7, лише
      падел-клуби.
- [x] PD1.6 Картка й сторінка оферти: позначка «Падел», рівень без слова NTRP.
- [x] PD1.7 `/clubs` і вибір клубу — лише клуби активного спорту; `sports` у `clubs.json`.

- [x] PD1.9 Тести: `lib/sport`, схема оферти, фільтри стрічки.

Стан на кінець сесії — у розділі «Журнал» нижче.

## PD2 — Профіль і решта списків (сесії 1–2)

- [x] PD2.1 Профіль: окрема сторінка `/profile/padel` («Мій падел») — рівень 1–7 і сторона гри
  (ліва / права / обидві), обидва необов'язкові. В онбординг не додано: тенісист не має
  відповідати на питання про падел. Показ: `profile-hero`, публічний профіль, рядки гравців на
  падел-оферті (`player-link`), кандидати для запрошення, експорт даних.
- [x] PD2.2 Підказка в падел-стрічці для залогіненого гравця без рівня падел.
- PD2.3 `PlayIntent.sport` («Шукаю гру») + стрічка намірів і сповіщення за спортом. До PD2 наміри
  лишаються тенісними, а в падел-режимі посилання на них сховані.
- PD2.4 «Грати сьогодні» за спортом уже фільтрує оферти (PD1); додати наміри.
- PD2.5 «Мої ігри», дзвіночок, листи й push: назва спорту в тексті, де список змішаний.
- PD2.6 Лендинг і метадані: «теніс і падел», тексти EN/PL. Зроблено лише `/clubs`: надпис і
  кнопка за спортом, фільтр покриття схований для падел.
- PD2.7 🧑 Власник: зібрати падел-клуби Кракова в `prisma/data/clubs.json`
  (`"sports": ["PADEL"]` або `["TENNIS","PADEL"]`), `pnpm clubs:load`. Агент даних не вигадує.
- PD2.8 `Court.sport` для партнерських клубів з обома спортами; сітка бронювання за спортом.

## PD3 — Найкраще з HiPadel (сесія 3)

- PD3.1 **Тип матчу**: enum `MatchGender` (ANY / MEN / WOMEN / MIXED) в оферті, поле форми, фільтр
  стрічки, перевірка статі при заявці. Для обох спортів.
- PD3.2 **Приватний матч**: `SparringOffer.visibility` (PUBLIC / PRIVATE). Приватна не потрапляє в
  стрічку, push і кандидати; відкривається лише за посиланням.
- PD3.3 **Інвайт-посилання**: токен на оферті; хто відкрив і ввійшов — одразу отримує прийняте
  місце (як прийнятий інвайт S1), доки є місця. Ліміт і відкликання токена автором.
  ⚠️ RLS/доступ: окремий запис у `decisions.md`.
- PD3.4 **Улюблені гравці**: таблиця `player_favorites`, кнопка на профілі, список у профілі,
  «запросити улюблених» на своїй оферті, push «улюблений гравець створив гру» (в межах денного
  ліміту push).
- PD3.5 **Фільтр за клубом** у стрічці.

## PD4 — Результати й рейтинг падел (сесія 4)

- PD4.1 Рішення в `decisions.md`: формула ELO для пар (середнє пари проти середнього пари, зміна
  порівну обом), окрема колонка `padel_elo` і `padel_matches_played`; стартове ELO з `padelLevel`.
- PD4.2 Результат парного матчу: хто з ким грав (2 пари з 4 учасників), рахунок, підтвердження
  будь-ким із протилежної пари, автопідтвердження через 72 год. Нинішній `MatchResult` прив'язаний
  до одного join — потрібна нова модель `DoublesResult` (нова таблиця, старі дані не чіпаються).
- PD4.3 Заодно це відкриває результати для тенісних пар.
- PD4.4 Лідерборд за спортом (розділ досі схований прапорцем `leaderboard`).
- PD4.5 Відгуки після матчу (W) і no-show для четвірки.

## PD5 — Клуби й запуск падел (сесія 5)

- PD5.1 Події клубу: оголошення від `ClubStaff` у панелі клубу, стрічка подій на сторінці клубу,
  push фоловерам (разом із прапорцем `clubChat`).
- PD5.2 Карта: шар падел-клубів, іконки за спортом.
- PD5.3 E2E: один новий сценарій «перемкнути на падел → створити гру → побачити в стрічці»
  (у межах чотирьох потоків AGENTS.md §7 — розширення потоку 2, не новий spec).
- PD5.4 Аналітика: властивість `sport` у подіях `offer_created`, `join_requested`.
- PD5.5 Оновити `AGENTS.md` §1 (опис проєкту) і `ROADMAP.md`.
