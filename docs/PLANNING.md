# PLANNING.md — план реалізації MVP MatchFinder Kraków

Правила розробки (стек, команди, розмір PR, межі дозволеного) — у [AGENTS.md](../AGENTS.md);
цей план їм підпорядкований. Це робочий документ: нові підзавдання додаються, завершені
відмічаються `- [x]`, і нічого не видаляється без записаної причини — історія рішень важлива.

## Позначення

- **ID** (`3.4`) — посилання в назві гілки, коміті та PR (`feat/3.4-offer-create-action`).
  ID стабільні: додане пізніше підзавдання отримує наступний вільний номер в epic, навіть якщо
  стоїть у середині розділу — так старі посилання в комітах не ламаються.
- **Розмір:** S — кілька годин · M — пів дня–день · L — 1–2 дні (у плані L немає: усе, що
  виходило L, розбито далі).
- **Залежить від** — ID, які мають бути змерджені раніше.
- **ADR** — підзавдання-рішення: результат — датований запис у `.agents/decisions.md`, а не код.
  Там, де без рішення людини не можна рухатись далі, це позначено 🧑.
- Загальний DoD для **кожного** підзавдання (не повторюється нижче): `pnpm build`, `pnpm lint`,
  `pnpm typecheck`, `pnpm test` зелені; у diff немає `console.log`, закоментованих блоків і
  сторонніх файлів; PR має абзац «чому». Нова логіка в `lib/` → юніт-тест у `tests/`.
  Новий користувацький флоу → Playwright happy-path (AGENTS.md §7).

## Ухвалені рішення (2026-09-24)

Відповіді власника на відкриті питання плану. У `.agents/decisions.md` їх переносить 0.2.

- **Мова інтерфейсу:** англійська (поки що). Інфраструктуру i18n не будуємо, доки не знадобиться.
- **Вхід:** і magic link, і Google OAuth.
- **Формат оферти:** синґл за замовчуванням, парна гра — опційно. У парній оферті автор може
  позначити «вже маю партнера» (тоді потрібно 2 гравці, інакше 3); партнер у MVP — не прив'язаний
  акаунт, лише позначка.
- **Чат:** окремий приватний тред на кожну заявку (автор ↔ гравець); для парної гри прийняті
  учасники додатково мають спільний груповий тред.
- **ELO:** рахуються лише синґли; результати парних ігор у MVP не вносяться.
- **Вік:** мінімум 16 років. Зберігаємо дату народження (приватно), публічно показуємо лише вік.
- **Домену немає:** email-частина працює в тестовому режимі (листи лише на адресу власника);
  власний домен потрібен до публічного запуску (5.13).
- **Хостинг:** на старті тестує лише власник, без монетизації — безкоштовні плани Vercel Hobby і
  Supabase Free достатні. Free-проєкт Supabase може призупинятись при неактивності — це нормально
  для етапу тестування.
- **`main` захищена** (0.22): лише через PR із зеленим CI, squash-merge, лінійна історія.
- **Прийняті доповнення до вихідних epics:** 0.22 (захист `main`), 0.23 (Playwright),
  1.19 (auth-листи через Resend), 6.19 (моніторинг помилок).
